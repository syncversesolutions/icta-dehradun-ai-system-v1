CTA Development Rules

Repository Status

THIS REPOSITORY IS UI-STABLE.

The current dashboard architecture, navigation, layouts, themes, and page organization are considered stable and should not be redesigned unless explicitly requested.

⸻

Protected Areas

Do not modify the following without explicit instructions:

* app/layouts/
* app/themes/
* app/styles/
* app/pages/intelligence_center/
* app/pages/operations_center/
* app/pages/observability/
* app/layouts/navigation.py
* app/layouts/sidebar.py

Do not:

* redesign the UI
* rename pages
* move pages
* change navigation structure
* change theme architecture
* change visual design

⸻

Development Philosophy

Prefer:

* adding new modules
* adding new services
* extending existing capabilities
* creating clean APIs
* maintaining backward compatibility

Avoid:

* large refactors
* architectural rewrites
* UI redesigns
* unnecessary file renaming

⸻

Sprint 2 Priorities

Focus development on:

1. Occupancy Intelligence
2. Dependency Graph
3. Cross-Domain Reasoning
4. Prediction Engine
5. Scenario Simulation
6. Global Signal Aggregation

⸻

Codex Rules

When implementing features:

1. Keep changes limited to the requested feature.
2. Prefer creating new files over modifying existing ones.
3. Explain architectural decisions.
4. Minimize file modifications.
5. Avoid changing UI components unless requested.
6. Do not modify runtime-generated files.
7. Do not modify state snapshots.
8. Create reusable services and modules.

⸻

Runtime Files

Do not edit:

* runtime/
* system/state/
* system/autonomy/state/
* system/memory/history/
* system/prediction/

unless specifically requested.

These files are generated by system execution.
